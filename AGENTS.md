# Правила проекта для Codex

## Приоритеты

1. **Без ошибок:** примеры арифметически верны; каждый шаг уравнения равносилен предыдущему в рассматриваемом случае; нет опечаток и новых терминов без объяснения.
2. **Ясность:** короткие прямые предложения; одна идея на иллюстрацию; не употреблять обороты «бла-бла, но…», ненужные оговорки, риторические украшения.
3. **Верность автору:** сохранять утверждённые формулировки и композицию; не заменять согласованный текст собственным стилем; обсуждать только конкретные сомнительные места.
4. **Внимание ребёнка:** минимальная нагрузка на устный счёт, несколько однотипных примеров для автоматизации процедуры, согласованные цвета и размеры.
5. **Редактируемость:** рабочий формат Inkscape SVG, текст остаётся текстом, рамки и стрелки — отдельными объектами, PDF — экспорт для распространения.

## Зафиксированное решение

- Блок 01: утверждённое содержание в `content/01-intro-APPROVED.md`.
- Авторский стиль: `design/01-original-by-parent.svg`. Изменять его только в новой копии.
- Важная фраза, использовать **дословно**:
  «Решить уравнение — значит узнать, какое число спрятано за x. Это число называется корнем уравнения.»
- Для вычислительного примера: одна горизонтальная цепочка; очень маленькие **одинакового размера** цифры 1, 2, 3 над соответствующими знаками «=», аккуратно по центру.
- Для решения уравнения: строки одна под другой, знаки «=» в одной колонке; номера строк 1–4 одинакового размера и по одной оси; следить за промежутками между текстовыми блоками.

## Визуальный язык

- Синий: левая часть и знаки равенства/направление работы (строго различать контекст).
- Охристый: правая часть на схеме устройства уравнения.
- Нейтральный тёмный: основной текст и вычисления.
- Цвета, толщина штриховых рамок, типографические размеры едины на всех страницах.
- Размеры шрифта использовать из малого фиксированного набора: заголовок, подзаголовок, текст, вспомогательная подпись, микронумерация. Не создавать случайных промежуточных размеров.
- Несколько уровней внимания: главное правило заметнее пояснения на 1–2 пункта, а не за счёт пестроты.
- Иллюстрации должны доказывать/объяснять конкретное действие. Декоративных картинок не нужно.

## Процесс

1. Вначале текст и контроль примеров. Отдельно согласовать спорные места.
2. Затем SVG и компоновка, ориентир — 1–2 А4 для родителей, 1 А4 для ребёнка; не уменьшать шрифт до нечитаемости ради формального лимита.
3. После изменений делать предпросмотр/визуальную проверку **для себя**, пользователю прежде всего отдавать SVG и итоговый PDF. Не создавать PNG как отдельный обязательный артефакт.
4. Перед финальной выдачей: `python3 qa/check_examples.py`, орфография, проверка логики, все надписи на месте и не наезжают друг на друга, правильное число страниц и поля печати.
5. В финале перечислить конкретные изменения, замечания и что ещё требует подтверждения.

**Математические ограничения:** перенос с изменением знака — сокращение прибавления/вычитания одного и того же числа в обеих частях. «Знак путешествует с числом» относится к перестановке слагаемых **в пределах одной части**. Не делать из него универсальное правило перестановки произвольных кусочков выражений.
